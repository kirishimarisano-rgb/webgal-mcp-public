# webgal-mcp v0.2.0 Windows 验收与发布候选说明

**本机发布候选已通过 Windows 与 Terre 验收，等待合并及发布确认。** 本页列出 v0.2.0 的候选交付范围、实测结果和发布条件。

候选版本号为 `0.2.0`，包属性为 `private: true`，源码使用 PolyForm Noncommercial 1.0.0。

## 候选范围

### NEXT-01 连接诊断

`webgal_status(projectId)` 汇总工程文件可读性、Terre 响应与 API、工程映射、写入工具开关及人工交接要求，并通过按排查顺序排列的 `nextSteps` 给出下一步。检查结果会区分 `projectFiles.readable`、`connectionStatus`、`mappingStatus`、`writeToolsEnabled` 和 `handoffRequired`。

诊断只返回解决问题所需的状态、固定提示和错误码。连接检查不创建写会话，也不修改工程。`writable: false` 只描述当前没有无会话写入权限，实际是否能写还需核对 `writeToolsEnabled` 与人工交接。

### NEXT-02 上手流程

[README 快速上手](../README.md#快速上手) 提供完整路径：配置本机工程，接入 Codex，用 `webgal_status` 检查连接，用 `scene_read` 读取开场，再按“草案、Terre 保存与关闭编辑页、用户明确交接、重新生成计划、应用、回到 Terre 预览”完成一次小修改。

[连接与试改排查](tool-reference.md#连接与试改排查) 覆盖 MCP 未登记、工程文件不可读、Terre 无响应、映射未验证、写入未启用、交接过期和版本冲突等常见问题。

### NEXT-03 `project_scan`

`project_scan` 只读检查已保存的 `game/scene` `.txt` 场景，按相对路径排序并跳过链接。报告区分确定缺失的本机静态引用与无法静态确认的引用，并给出场景相对路径、能够确定时的行号、安全目标及原因。

`scope` 记录总场景数、已检查数、未完成数与下一页入口，`stopReason` 标记上限。单批最多 100 个场景，清单最多 10,000 项，单场景最多 128 KiB，场景与问题详情合计最多 128 KiB，并受 5 秒预算约束。动态引用、编辑器缓冲区和外部 URL 留给人工预览核对。扫描不执行脚本、不访问外部 URL、不自动修复或导出。

### NEXT-04 / NEXT-05 大素材候选

候选阶段只为新建的 `game/background/**` 与 `game/bgm/**` 启用流式导入，单文件最多 16 MiB（16,777,216 B），同一批的流式大素材合计最多 32 MiB。来源按 64 KiB 分块读取并计算 SHA-256，计划保存来源身份与版本，媒体内容不进入 MCP 输出或日志。

文本与其他素材继续使用单文件 1 MiB 上限。走原有缓冲写入的部分继续使用每批 4 MiB 上限。两类额度分别计算。大素材沿用现有 Write Coordinator 的人工交接、来源复核、目标不存在检查、计划、故障记录与恢复流程，已存在的同名目标不覆盖。

当前原型中，每个计划来源描述符为 134 B。该数值是当前样本的计量结果，发布时应随计划格式一并复核。

## 已记录的原型证据

以下结果来自受控原型，仅证明候选技术路径，不等同于真实 Windows GUI 发布验收。

| 检查 | 结果 |
| --- | --- |
| 12,588,853 B PNG | 流式复制后源与目标 SHA-256 相同 |
| 16,777,216 B WAV | 流式复制后源与目标 SHA-256 相同 |
| 16 MiB + 4 B 来源 | 超过单文件上限并拒绝 |
| 注入的 `ENOSPC` | 原型收到 `ENOSPC`，本次暂存已清理，目标未发布 |
| 目标同名 | 拒绝，不覆盖已有目标 |
| 计划后来源变化 | 报告 `SOURCE_CHANGED`，目标不发布，也不覆盖已有文件 |
| 进程中断 | 留下 114 B 计划记录和 64 KiB 暂存，目标未发布 |

在 Windows 11（10.0.26200）与 Node.js 24.9.0 上，原型的 PNG 分段复制、同步和暂存回读分别用时 18.9、26.7 和 13.3 ms，WAV 分别为 26.4、15.6 和 18.3 ms。每次使用一个暂存文件，峰值暂存空间等于该素材大小。原型进程峰值 RSS 为 61,044 KiB，现有计划基线进程为 105,636 KiB。两个进程加载的模块和执行的步骤不同，这些数据用于记录各自开销。

在候选生产路径的自动化测试中，注入 `ENOSPC` 产生 `STORAGE_FULL`，确认目标缺失且清理了本次暂存。测试还覆盖来源变化、同名拒绝、v1 记录兼容、应用后重放，以及真实子进程在复制中和发布后中断，随后由 `recovery_inspect` 核对实际磁盘。磁盘空间不足使用故障点注入。

从干净候选副本运行了 `npm ci`、`npm run check`、`npm test` 和 `npm pack --dry-run --json`。326 项测试通过，拟分发清单共 46 项。专用边界样本通过了 16 MiB 单文件和 32 MiB 批次写入，超过两项边界的请求均被拒绝。

真实 Codex CLI 0.167.0-alpha.4.1 在干净候选副本上成功调用 `webgal_status` 和 `project_scan`，连接到 WebGAL Terre 4.6.7.0 中的专用测试工程。同一工程的 MCP 只读复核完成 8 个场景的扫描，66 个文件的清单与 SHA-256 保持一致。

用户确认保存和交接后，在同一专用工程实际应用了三个新建操作。PNG 与 WAV 的磁盘内容和 Terre HTTP 返回字节均与来源 SHA-256 一致，暂存已清理。三项 v2 计划共 1,351 B，批次日志共 1,027 B。工程原有 66 个文件的清单与 SHA-256 保持一致。

2026-11-19，用户确认在 Terre 保存并重新打开测试场景后，两项素材引用仍然正确，预览中能看到背景并听到 BGM。随后通过只读 MCP 复核保存的场景，两项静态引用均存在，PNG 与 WAV 的字节数和 SHA-256 与导入时一致。
